# 普通通知日龄文案池与 APP 多语言

实施日期：2026-09-20。依据：[v1.0.1 需求第 5 章](https://pic6ktmsyi.feishu.cn/wiki/T4vOwfFKviXZBYkwCgFcH6xmnAc)，本地默认直接采用用户提供的五份 Downloads JSON，原字节不修改。

## 参数与默认池

| 日龄 | Firebase Remote Config key | 本地 assets | 条数 |
| --- | --- | --- | --- |
| D1 | `pushContentD1Json` | `pushContentD1Json.json` | 29 |
| D2 | `pushContentD2Json` | `pushContentD2Json.json` | 28 |
| D3 | `pushContentD3Json` | `pushContentD3Json.json` | 28 |
| D4 | `pushContentD4Json` | `pushContentD4Json.json` | 28 |
| D5 | `pushContentD5Json` | `pushContentD5Json.json` | 28 |
| D6 及以后 | 无单独 key | 当前有效 D1→D5 合并 | 默认 141 |

参数值为完整 JSON 对象文本（`schemaVersion: 2`、对应 `pool: D1…D5`、`defaultLanguage: en`、`contents`），不是 URL，也不需要外包参数名。`configVersion` 是运营版本标记，不参与选池和游标重置。

每个 key 独立采用有效新远程值；未配置、空值、损坏或池标识错误时，保留本进程有效池/上次有效缓存，否则使用该日的本地文件。五池组成一个内存快照后切换，单个坏池不会覆盖其他池。沿用现有 Firebase 获取时机和间隔，不增加实时监听或轮询。

新版普通通知不再读取 `pushContentJson` 及其旧缓存；旧数组 asset/解析测试保留作为旧协议参考，不进入新日池。没有新增 `pushContentD6Json`。

## 日龄与顺序

- 第一次启动进程时捕获当地自然日，在 IO 初始化时首次持久化；以后按当前当地日期差计算，D6 以后统一使用合并池。按自然日而非安装时间或累计 24 小时计算。
- 旧版没有保存这个首启口径，升级后的首次运行开始建立日龄，不将安装时间冒充历史首启时间。
- D1–D5 各自从首条开始顺序循环；D6+ 使用独立的合并池游标，保留原来的跨重启/后续日期连续轮播行为，不额外增加每天重置、发送次数限制或去重规则。
- 游标只按池区分，切换 APP 语言不会跳回首条。远程更新后按新池长度取模，避免越界。
- 首启日、六个游标及有效远程缓存位于 `noBackupFilesDir/push_day_content`。卸载重装从 D1 重新开始，不从云备份或设备迁移恢复旧日龄。写入采用 AtomicFile，均在推送 IO 路径完成。

## 语言选择

- 通知构建时通过 `NotificationHost.contentLanguageTag` 获取 APP 当前语言；应用内/系统应用语言优先，跟随系统时使用当前应用 Context 的 locale。冷启动等待已有 APP 语言恢复完成。
- 按“精确标签 → 同语言通用标签 → 约定区域版本 → 默认英文”匹配。无地区 `es` 和其他拉美地区采用 `es-MX`，明确 `es-ES` 使用西班牙版本；`pt`→`pt-BR`、`id`→`id-ID`、`hi`→`hi-IN`、`ja`→`ja-JP`、`ko`→`ko-KR`。
- 用户提供的文件含英文根文案及 `pt-BR`、`es-MX`、`es-ES`、`id-ID`、`hi-IN`、`ja-JP`、`ko-KR` 七组翻译。其他 APP 语言当前回退英文；远程可以增加受支持的 APP 语言翻译。
- `title`、`desc`、`buttonText` 作为一组选择；缺字段/空字段的翻译不使用。图标和动作编号始终取根条目，不允许翻译改变路由。
- 既有通知构建器、展示/点击/进入埋点使用选定后的文案快照，保持所见与上报一致。

## 业务编号

原 1–6、1001–1003 映射保留。为完整接收这 141 条内容，补齐文件已有的 `1004` 视频、`1005` 相似照片、`1006` 病毒扫描、`1007` 电池图标与路由。点击进入已有首页功能入口，沿用各自权限和病毒协议流程，不自动删除或清理。

大字号真机核验发现原普通通知展开模板的操作按钮固定 39dp（Android 13+ 为 32dp）会裁切文字，因此三套展开模板共用自然测量高度的按钮布局，各版本原尺寸保留为最小高度；常规字号外观不变。

本次没有调整自然/买量判断、发送触发、频次配置、常驻通知显示规则、双层屏幕监听、旧周期任务、通知权限、广告或自动清理策略。

## 有界处理

单日池最多 256 条、262,144 个 JSON 字符且 UTF-8 不超过 512 KiB；D6 是五个有界池的组合，不按单池 256 条截断。每条最多保留 32 个支持的语言标签；保持既有 id/title/desc/buttonText 的 100/120/500/40 字符上限。坏配置不缓存，缓存故障不覆盖已有有效池。

## 中文诊断日志

Logcat 按标签 `NotificationModule` 过滤，新流程统一使用 `[推送日池]` 前缀：

- 初始化输出首次启动日期、当前日期、实际日龄，以及 D6+ 合并总条数。
- 每个日池输出远程参数名、实际配置来源（远程/本进程有效池/上次有效远程缓存/本地默认）与条数。
- 远程为空或不可用、协议校验失败、缓存无效、缓存写入失败均有中文说明。
- 每次取文案输出真实日龄、所选池、当前序号/总条数、文案编号、动作编号、APP 语言、匹配语言、英文回退原因、下次序号和循环状态。

“文案选中”只表示内容选择完成，实际发送成功仍以原通知发布日志为准。日志不输出完整 JSON 或通知正文。沿用原日志开关：Debug 默认开启，Release 默认关闭；本次未改变开关策略。
