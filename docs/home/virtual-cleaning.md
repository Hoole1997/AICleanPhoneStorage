# 首页虚拟垃圾量与常驻通知 Clean 角标

按用户补充的规则实现：虚拟垃圾量只是首页/常驻通知的展示数据，不来源于真实本地扫描；本轮未清理状态保留同一个数，清理后满三分钟才允许下一轮重新生成。

## 状态和检查时机

`HomeCleaningState` 是 Application 持有的唯一进程内数据源，保存用户类型、本轮虚拟量、上次进入完成页的时间及去重标记。时间使用 `elapsedRealtime()` 单调时钟，避免手动调整系统时间影响间隔；不写 SharedPreferences、数据库或 Bundle。进程重启后不恢复上一次清理时间。

| 事件/条件 | 行为 |
| --- | --- |
| 首页 onResume | 检查一次；通知刷新产生的新状态也通过 StateFlow 同步到可见首页 |
| 常驻通知构建/刷新 | 从同一状态源检查并读取 Clean 角标，折叠/展开使用同一轮数值 |
| 自然用户 | 保持已清理展示，不生成虚拟量，Clean 无角标 |
| 买量用户从未进入完成页 | 首次检查生成一轮虚拟量，进入未清理展示 |
| 未清理期间再次检查 | 复用本轮数值，不重新随机 |
| 进入有效清理完成页 | 立即记录完成时间，清除虚拟量，首页显示存储概况，Clean 角标隐藏 |
| 距完成不足 180 秒 | 检查后仍保持已清理 |
| 满 180 秒后的下一次检查 | 生成下一轮虚拟量，首页/通知同时恢复未清理展示 |

没有独立三分钟倒计时、定时器或扫描任务。单纯时间流逝不发射状态，下一次检查才切换。虚拟量范围为 320.1–679.9 MB，保留一位且小数位非零，符合需求的 320–680 MB 范围和非整数要求。首页数值与通知角标共用同一个数值格式化入口。

所有已有通用完成页（垃圾、截图、压缩、大文件、未使用文件、通知清理）使用同一入口标记。页面把一次访问的 UUID 保存在实例状态，用来去重旋转/重建；保存的是访问标记，不是清理时间，因此重建不会延长三分钟。点击 Continue、关闭广告、仅完成扫描不会单独更新清理时间。

## 接入边界

- `HomeViewModel` 将清理展示状态与真实存储摘要组合。主卡不再读取扫描索引里的 junkBytes；清理详情、文件选择、删除和压缩逻辑继续使用真实索引与结果。
- `HomeCleaningSync` 使用与 SDK 相同的 ChannelUserController 归因口径，默认用户类型来自渠道配置；渠道存储读取在 I/O 线程执行。
- `CleanNotificationHost` 提供 Clean 角标。状态变化更新现有同 ID 通知，不另发一条通知；并复用模块的 Notific_Pull 事件刷新已有通知，使收到 FCM/已有模块刷新事件时能重新检查。没有改动 notification 模块源码。
- 来源模块的 15 分钟后台服务当前仍默认关闭。本次未启用后台保活，也没有新增 15 分钟任务；仅响应实际发生的现有刷新事件。
- 本次实现首页状态与现有 Clean 角标的数据联动。通知入口的 A/B 布局、App 数量角标及入口更名/跳转调整不属于本次状态逻辑变更，仍为现有实现。

## 验证

local/google Kotlin 编译、141 项单元测试、localDebug Lint（0 错误、139 条警告）通过。API 32 模拟器 6 项相关测试通过：验证首页与 RemoteViews 数字一致，清理后隐藏，三分钟边界恢复，同轮刷新不变，完成页旋转不重置时间，以及原有通知路由、权限渠道和文字边界。首页未清理/已清理截图已核验；页面测试的存储摘要是测试夹具，未冒充设备实际数据。
