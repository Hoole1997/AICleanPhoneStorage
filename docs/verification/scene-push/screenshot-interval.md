# 截图触发仅按远程间隔进入队列

2026-10-22 按用户要求，1105 截图场景删除固定 300000ms 等待，并移除已处理 URI/媒体项目过滤。

- 截图识别成功后，由 `ScreenshotSceneRules` 立即提交候选，`dueElapsed` 为当前时间。
- 每次媒体回调使用查询结果中的最新截图；同一 URI 后续再次识别仍会提交，不读取/写入重复过滤缓存。
- 调度层只按 `screenshotPushIntervalMinutes` 与上次实际发布时刻判断；间隔到达后进入现有 FIFO。重复回调不会从头重新计算截图间隔，同场景仍最多一个待处理候选。
- 原有目录、权限、图片写入完成及发布前有效性检查保留。下载单独处理，原去重、聚合与 5 分钟等待保持不变。
- 中文日志改为“识别成功，无额外等待，交由远程截图间隔判断后进入展示队列”；截图不再输出“已过滤重复媒体项目”。

验证：local 应用及测试编译、notification Lint、`git diff --check` 通过；notification 单元测试 136 项通过。新增回归用例验证：前一场景结束后截图立即播放，不额外等待 5 分钟；同 URI 在 10 秒、30 秒重复识别，远程间隔为 1 分钟时仍在第 60 秒发布。API 37 场景设备回归 9 项通过，日志见 `screenshot-interval-device-tests.txt`。

本次没有界面布局变更；未修改其他场景规则、远程参数或 google 渠道，未提交 Git。
