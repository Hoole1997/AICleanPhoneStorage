# Smart Cleaning

首页顶部 Smart Clean 接入真实扫描。权限与通用 Loading 都在结果页之前处理；广告仍是占位。完成后进入 Figma `5548:417` 的分类总览，点击分类进入分页文件列表。旧照片网格代码保留。详情只编辑选择，返回总览统一确认清理。

## 当前展示与扫描规则

当前入口只展示 APK、Temporary Files、Empty Folders、Ad Files，顺序固定。旧日志、空文件及照片分类/分析代码保留，当前扫描不运行照片分析，旧索引中的隐藏分类也不参与当前总览、容量汇总和批量清理。

| 分类 | 候选规则 |
| --- | --- |
| APK | 共享存储或授权目录中 `.apk` 后缀的安装包，大小写不敏感；包括 Download 和应用下载目录 |
| Temporary Files | `.tmp`、`.temp`、`.log`、`.part`、`.crdownload`，以及可访问的 cache/caches 目录中的文件，不设旧的 7/30 天门槛 |
| Empty Folders | 整棵子树不含任何文件，嵌套空目录分别计数，每个 0B；零字节文件、不可读项、符号链接、扫描深度截断均不能视为空 |
| Ad Files | 名称词段 ad/ads/advert 等及 AdMob、AppLovin、Vungle、Pangle、UnityAds、IronSource、Mintegral 等已知 SDK 特征；避免将 Download、road 等普通单词误判 |

每个文件只归一类：APK 优先，广告特征其次，临时文件最后。广告缓存不会同时计入 Temporary Files。根目录、Android/data、Android/obb 和压缩输出目录保持保护；不承诺能读取其他应用的私有缓存。

新扫描默认全选四类候选。返回详情、页面重建和同一扫描重复发布保留手动取消的选择。旧照片功能的参考图保护和删除前内容校验仍保留。

## 扫描容量动画

扫描弹框从 `0.0 MB`、0% 开始。后台按批次返回实际新增候选字节数，重复 URI 不重复累计；数字和进度条使用同一展示时间轴和同一个 View 层 Animator。固定 MB、一位小数，不在增长时切换单位。任务完成后以四分类摘要的准确字节数收尾；空目录及空扫描不会虚构容量。

进度百分比仍是扫描工作量估计，不能解释为精确剩余时间。系统关闭动画时直接更新，退到后台/取消扫描/销毁弹框时停止动画。结果页使用相同字节数，保留其自动 MB/GB 格式化。

## 性能与取消

- 复用 `FileScanRepository`、`FileScanSources`、SQLite/Paging 和 `FileOperationEngine`。没有新建一套全量文件列表或独立后台服务。
- 文件元数据每 200 条写入索引，详情每页 60 条、最多驻留 240 条。
- 共享存储使用最多 64 层的后序遍历；SAF 队列与目录关系写入临时 SQLite，按深度从子目录向父目录传播非空状态，只打开一个 Cursor，不在内存保存全量目录树。
- 所有扫描/图片/数据库工作使用既有有界 TaskExecutor。读取循环协作取消，进入后台停止用户触发的前台任务；不轮询、不持有后台唤醒锁。
- 扫描被取消或失败时只丢弃当前临时索引，不触碰原文件。不可读、已变化或不支持的照片记录在“分析跳过”数量中，避免假报全量完成。

## 选择、删除与数据升级

共享索引 v5 在临时目录队列保存文档能力 flags，保留既有文件、选择和操作记录。目录身份复用 MIME 字段，空目录以子目录优先顺序进入操作队列。删除前逐项重新验证授权范围、类型、删除能力与当下子项，绝不递归删除目录内容；未选中的子目录或扫描后新增文件会阻止父目录删除。参考图保护在逐项选择、全选、冻结操作和执行层均检查。

2026-09-15 Android 10 日志定位：两次清理中，Clash 的 `FilesProvider` 对同样的 5 个 `providers` 条目返回 `invalid path`，并非 0B 导致删除未执行。垃圾入口的 SAF 现在仅接受 `com.android.externalstorage.documents` 的本地共享存储树；已有授权和目录选择流程保持不变；按用户最新要求，不弹出重选或警告弹框，在扫描层直接过滤第三方提供者整棵目录树。全部被过滤时正常完成扫描，结果为零个候选；其他文件功能保持原有来源规则。

SAF 空目录扫描读取 `COLUMN_FLAGS`，只有 `FLAG_SUPPORTS_DELETE` 为真才纳入候选。不支持删除的空子目录会阻止其父目录被判定为可清空，但其中独立可删的子项仍可正常扫描。删除前再次查询能力，缺失标志、能力撤回或目录新增内容均拒绝删除；旧垃圾操作快照的第三方来源也在执行前拦截。不修改提供者返回的不透明 documentId，不拼接真实路径兜底删除。

静默过滤版本验证：local Debug 构建、Lint、173 项 app 单元测试和 API 32 模拟器 16 项设备回归通过。第三方目录树不访问提供者、不生成候选，并正常报告扫描完成；正常目录删除、删除能力变化、受保护父目录、旧结果和索引升级保护均通过。重选弹框、专用状态和对应多语言文案已移除。原小米 Android 10 真机未连接，未在该机复验。


总览与详情共享同一磁盘选择状态。选中项在用户确认时冻结；删除前重新验证范围、大小、修改时间及参考图是否存在。完全重复照片在删除前会再次计算候选和参考图的 SHA-256，连“同大小、同时间戳但内容已变化”也会拒绝删除。MediaStore/SAF/直接文件删除沿用已有系统确认与分批流程。

`CleanupOperationCoordinator` 从旧结果页提取，四类清理和总览共用确认、系统授权与结果展示。照片压缩的原图保护流程保留；静态 PNG 检查复用到视觉分析。

首页现在读取真实存储与最近一次 Smart Cleaning 摘要；清理当前结果后，分类和首页摘要随索引变化更新。摘要反映最近扫描，不是对设备所有变化的实时监控，临时索引仍遵守三天保留规则。

## 原生界面

插画、分类勾选框、箭头、临时文件图标均从 Figma 原节点导出，并提供五档密度 WebP；来源和 SHA-256 记录在 `design/figma/junk-cleaner/assets.json`。照片缩略图来自真实文件，普通文件/APK 使用原版文件图标。

总览插画与容量作为 RecyclerView 头部，横屏/大字体时可以整体滚动；数字和单位按 baseline 对齐并自然测量高度。底栏高度变化会同步调整列表留白。分类详情使用白底原生列表/网格及通用选择组件；包含必要的候选规则说明和 Keep 标记。
