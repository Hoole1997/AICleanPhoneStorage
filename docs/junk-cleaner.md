# Smart Cleaning

首页顶部 Smart Clean 接入真实扫描。权限与通用 Loading 都在结果页之前处理；广告仍是占位。完成后进入 Figma `5548:417` 的分类总览，点击分类进入 `5548:574 / 681 / 833` 对应的列表或照片网格。详情只编辑选择，返回总览统一确认清理。

## 分类规则

| 分类 | 候选规则 |
| --- | --- |
| APK | 共享存储或用户授权目录里的非空 APK 安装包；删除安装包不会卸载已安装应用 |
| Temporary Files | `.tmp`、`.temp`、`.part`、`.crdownload` 且至少七天未修改 |
| Old Logs | `.log` 且至少三十天未修改 |
| Empty Files | 至少七天未修改的零字节普通文件 |
| Duplicates | 相同文件大小候选经完整 SHA-256 校验，内容相同的照片分组 |
| Similar | 七天时间窗口内，宽高比、平均亮度/颜色及 dHash 接近的视觉候选 |
| Review Quality | 分辨率低于约 30 万像素，或缩略图细节/对比度都较低的候选 |

规则不把“年代久远”当成垃圾文件的充分条件；普通文档不会仅因为长期未修改而被 Smart Cleaning 选中。无法判断时跳过。最近写入的临时文件、其他应用私有目录、压缩输出目录不纳入自动垃圾分类。

照片相似、清晰度只是可解释的启发式，可能漏报或误报，不代表照片无价值。默认没有预选；每组重复/相似照片会保护一张参考图，用户不能将其全选进操作。视觉组优先保留分辨率更高的参考图；完全重复组保留较早的一张。视觉分析支持 JPEG 和静态 PNG，不把动画 PNG 的首帧当成完整内容；其他格式仍可做完整文件重复校验。

## 性能与取消

- 复用 `FileScanRepository`、`FileScanSources`、SQLite/Paging 和 `FileOperationEngine`。没有新建一套全量文件列表或独立后台服务。
- 文件元数据每 200 条写入索引，详情每页 60 条、最多驻留 240 条。SHA-256 使用 64 KB 缓冲，只对相同大小的照片候选计算。
- 视觉分析一次解码一张，采样后最长边约 128px，提取 64×64 灰度特征；只保留最多 64 个参考特征，不做图库全量两两比较。因此极大图库或时间相隔较远的相似照片可能漏报。
- 所有扫描/图片/数据库工作使用既有有界 TaskExecutor。读取循环协作取消，进入后台停止用户触发的前台任务；不轮询、不持有后台唤醒锁。
- 扫描被取消或失败时只丢弃当前临时索引，不触碰原文件。不可读、已变化或不支持的照片记录在“分析跳过”数量中，避免假报全量完成。

## 选择、删除与数据升级

共享索引升级到 v2，为文件增加分类、分组、参考图和内容校验字段；v1 文件记录及勾选状态迁移保留。参考图保护在逐项选择、全选、冻结操作和执行层均检查。

总览与详情共享同一磁盘选择状态。选中项在用户确认时冻结；删除前重新验证范围、大小、修改时间及参考图是否存在。完全重复照片在删除前会再次计算候选和参考图的 SHA-256，连“同大小、同时间戳但内容已变化”也会拒绝删除。MediaStore/SAF/直接文件删除沿用已有系统确认与分批流程。

`CleanupOperationCoordinator` 从旧结果页提取，四类清理和总览共用确认、系统授权与结果展示。照片压缩的原图保护流程保留；静态 PNG 检查复用到视觉分析。

首页现在读取真实存储与最近一次 Smart Cleaning 摘要；清理当前结果后，分类和首页摘要随索引变化更新。摘要反映最近扫描，不是对设备所有变化的实时监控，临时索引仍遵守三天保留规则。

## 原生界面

插画、分类勾选框、箭头、临时文件图标均从 Figma 原节点导出，并提供五档密度 WebP；来源和 SHA-256 记录在 `design/figma/junk-cleaner/assets.json`。照片缩略图来自真实文件，普通文件/APK 使用原版文件图标。

总览插画与容量作为 RecyclerView 头部，横屏/大字体时可以整体滚动；数字和单位按 baseline 对齐并自然测量高度。底栏高度变化会同步调整列表留白。分类详情使用白底原生列表/网格及通用选择组件；包含必要的候选规则说明和 Keep 标记。
