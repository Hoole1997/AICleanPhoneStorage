# 列表空状态检查

统一组件 `core/ui/empty/EmptyStateView` 使用 Figma `5659:598` 原版机器人 WebP（140dp），文案为 “No data available”，Roboto Regular 16sp、#A1A1A1，间距 12dp。来源和五档密度资源记录在 `design/figma/empty-state/assets.json`。

| 页面 | 处理 |
| --- | --- |
| 首页 | 固定工具入口不是数据列表；保留未扫描、加载、错误状态，不因没有扫描结果隐藏首页 |
| Network Traffic | 成功查询且应用列表为空时显示空布局；保留日期筛选和统计/权限说明；两个渠道都不可读时显示错误与重试 |
| Clear Notifications | 应用目录成功加载且为空时显示空布局；加载/失败不误报无数据，保留必要连接/规则提示 |
| App Manager | 等列表 Diff 提交完成后显示空布局；刷新中/失败时隐藏空态 |
| Photo Compress | 分页实际提交零条数据后显示空布局，隐藏估算头部和无效压缩按钮 |
| Large Files / Unused Files | 统一空布局，保留类型、大小、日期等筛选入口；无效清理与全选隐藏 |
| Screenshots | 统一空布局，无数据时隐藏清理/全选 |
| Smart Cleaning 总览 | 所有分类都没有可清理候选时显示空布局，隐藏无效分类与清理按钮；初始摘要读取显示进度 |
| 垃圾分类详情 | APK、临时文件、旧日志、空文件、重复、相似、Review Quality 全部复用分页空态；空时使用统一渐变背景，隐藏说明、全选和操作栏 |

Paging 的初始 NotLoading 不代表已经成功加载。`CleanupListStateRenderer` 同时等待页面提交及成功加载状态；使用 Presenter 同步监听，避免异步收集旧 Loading 事件将已提交状态覆盖，导致空态一直不显示。读取失败使用独立重试控件。

保留参考图的照片列表仍有实际条目时，不因“可选数量为零”显示空态。分类总览按可清理候选计数判断，详情则按实际分页条目数判断。

组件无动画或数据任务；小屏/大字体下内容可滚动。用于带头部的 RecyclerView 时填充剩余空间，布局监听在条目离开时解除。

设备测试覆盖分页加载/空/错误/恢复状态、不可用流量、通知错误、小高度大字体，以及实际四类清理页、七个垃圾分类详情、垃圾总览与应用管理空数据入口。测试不扫描或删除用户文件、不修改系统权限。
