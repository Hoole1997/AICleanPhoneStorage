# 扫描加载状态恢复

用户反馈一次“动画仍转、进度停止”的现象，未提供具体功能/停留数值；当前进程没有采集到对应异常日志，不能把本次现场归因于某个已确认触发动作。

已处理的代码风险：

- 四类首页入口统一通过 `observeEntryState` 在 RESUMED 收集状态，与弹框/跳转的渲染条件一致。暂停期间产生的进度和终态会在恢复时重放，避免只恢复弹框动画而没有更新状态。
- `TimedEntryLoader` 把内部取消和未分类异常转为可处理的失败；用户取消、后台取消仍按结构化取消传播。入口任务结束后，如果仍是本次请求的 Loading，就进入失败出口。
- 连续 60 秒没有新的实际 TaskProgress 变化时，先发布失败状态，再协作式取消任务。扫描总时长可以超过 60 秒；处理数量仍有变化时，即使整数百分比相同，也不会误判超时。完成展示阶段不做停滞判定。
- 失败/进度回调按请求 ID 匹配；旧请求迟到的失败、旧弹框的取消不覆盖或取消新请求。
- UI 不把未完成的扫描强行推进到 100%。系统 I/O 可能不能立即取消，但界面不必等待其清理完成才提示失败；只读扫描的临时索引仍按原流程回收。

验证覆盖内部取消、外部取消、阻塞清理、真实进展、重复无变化报告、失败重试、迟到旧失败，以及暂停/恢复时进度重放和终态关闭弹框。此验证不等同于复现用户当时的现场。

通用扫描弹框广告 Key 为 `native_scanning`；与扫描进度任务独立，测试开关继续保持 `return true`。
