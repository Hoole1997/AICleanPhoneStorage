# Network Traffic 实现与验证

## 当前交互

- 首页点击 Network Traffic → 在首页完成使用情况权限引导和通用 Loading → 数据准备就绪后进入结果页。
- 授权优先使用 `ACTION_USAGE_ACCESS_SETTINGS` + `package:应用包名` 直达本应用开关页；系统不支持时才回退授权列表，应用不自动开启权限。
- API 24–28 的可选电话权限也在首页处理；拒绝可继续查看 Wi-Fi。API 29+ 汇总移动网络时不读取 subscriberId。
- 日期采用本月、上月、最近24小时。页面内切换日期只展示顶部局部进度条，不弹 Loading、不展示广告、不增加等待。
- Manage 打开系统应用详情页；共享 UID 提供应用选择，不能直接强制停止其他应用。

## Loading 的统一时间轴

用户要求入口广告位有展示时间。每次入口查询随机选取一次 **2–4秒** 展示窗口，使用单调时钟，旋转不重新随机。

`EntryLoadingProgress` 将真实进度和展示时间组合：

- 计数、百分比、进度条从同一帧产生，展示数量始终不超过实际完成数量。
- 即使真实查询立即返回85个应用，也从0/85按展示窗口逐步推进，不先显示85/85再等待。
- 最后100ms显示完成帧；这100ms包含在随机总时长内。慢查询超过展示窗口时，不再追加等待。
- 系统查询尚无应用计数时使用未知进度；无应用结果显示“Preparing results”，不编造应用数量。
- 进度展示每50ms至多更新一次，相同整数状态被StateFlow合并；等待使用协程delay，关闭、退后台、取消或超时会取消等待及其子计时任务。
- 广告仍是静态槽位，没有接入广告SDK。展示进度不回写Repository，不影响真实流量数据。

## 架构与性能

首页入口与结果页分别持有页面级 NetworkTrafficViewModel，复用同一任务控制逻辑。入口模式按状态控制权限/弹框/导航，结果页模式不参与入口广告时长。

`TrafficSnapshotTransfer` 仅保存一份有效期60秒、只能消费一次的摘要，用令牌交接。Intent不传大列表，进入页面不重新执行刚完成的查询。进程死亡后令牌失效，结果页重新读取；权限缺失则回首页入口。

NetworkStatsManager查询与PackageManager读取在受限I/O调度器执行；Repository的Mutex保证该模块只有一个真实查询在途。取消不强杀Binder线程，旧请求返回后会被取消状态/请求ID拦截。NetworkStats始终在finally关闭。

Bucket按UID流式聚合，移动/Wi-Fi与上传/下载累加，字节使用Long。列表只存轻量数据；42dp应用图标按可见项加载，按字节上限2MiB缓存，离开页面取消图标任务并清空缓存。没有服务、VPN、唤醒锁、后台轮询或扫描用户文件。

固定返回、移动、Wi-Fi、关闭及旋转图标使用Figma原版WebP，原件在design/figma/network-traffic/source。

## 测试

- 单元测试覆盖时间范围/夏令时、Long溢出、一次性摘要交接、权限后才加载、取消后不导航、快速切换日期、超时、入口2–4秒等待、快慢查询、85/85进度同步及零应用。
- 真机测试覆盖首页先弹Loading再进入页面、关闭后不延迟跳页、日期切换无弹窗、当前应用权限详情Intent。
- 使用用户已授权的测试机读取真实流量；测试不通过appops/pm修改权限。
- 未做API24–28实机兼容、长期耗电和大量应用压力测量；系统统计有更新延迟，不是运营商账单或实时网速。
